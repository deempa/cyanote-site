Markdown and text files on Windows: what opens them, and what keeps them

By Cyanote · 30 September 2026 · 10 min read
  • Notes
  • Windows
  • Markdown
  • How-to

You download a project, or someone sends you notes, and there is a file called README.md. You double-click it and Windows either opens it in something odd or asks what you would like to open it with, as if you ought to know.

The short answer: a .md file is plain text with a few conventions — # for a heading, - for a list item, ** around bold. Anything that can open a .txt file can open it. The only questions are whether you want to see the formatting rendered, and whether you want Windows to remember your choice.

Let me go through what Windows gives you for this first, checked against Microsoft's own pages, because for plenty of people it is the whole answer. Then the thing I make, and exactly what it does with these files.

Opening a .md file with what you already have

Notepad

Right-click the file, choose Open with, pick Notepad. You get the text exactly as written: the hash marks, the asterisks, the lot. For reading a README or fixing a typo, that is fine, and it is what a Markdown file was designed for — readable without being rendered.

On Windows 11, Notepad has also been learning Markdown properly. Microsoft began rolling out text formatting in Notepad to Windows Insiders in May 2025: a formatting toolbar, bold and italic, links, simple lists and headings, with "Markdown style input and files". The same post says you can switch between the formatted view and the raw Markdown syntax from the View menu or a toggle in the status bar, and turn formatting off entirely in Notepad's settings. A later Insider build added tables, and Microsoft's Notepad release notes list, for July 2026, a fix so that formatting "is now applied properly" in both .md and .markdown files, in a version going out to Insider channels up to Release Preview.

What I could not find is a Microsoft page saying this has reached every Windows 11 PC, so I will not claim it has. The practical test takes ten seconds: open a .md file in Notepad and look for the formatting toggle in the status bar. If it is there, you have it. If not, your Notepad shows the raw text, which still works. Microsoft's posts describe this on Windows 11; on Windows 10, expect plain text.

VS Code

If you already have Visual Studio Code installed, it is the best free Markdown viewer on the machine. Microsoft's documentation says it supports Markdown files out of the box, no extension needed: Ctrl+Shift+V toggles a rendered preview, and Ctrl+K V opens the preview side by side with the source, so you can type on the left and watch the result on the right.

I would not install VS Code only to read a README. It is a programmer's editor and it looks like one. But if it is already there, it is the answer.

Making Windows remember

Picking an app once from Open with opens that file. To make every .md file open in the same app, Microsoft's page on changing default apps gives the route: Settings > Apps > Default apps, then type the extension — .md — into the search box and choose the app. The same works for .txt, .markdown or anything else. You can also go the other way on that page: select an app to see which file types it can open, and change them from there.

When that is enough

Be honest with yourself about what you are doing with these files.

You read the odd README. Notepad. You do not need anything else, and you will not miss a preview.

You write Markdown for a project — documentation, a static site, notes that live in a Git repository next to code. VS Code, or whatever editor you already use for the project. The files belong to the project, the project's tools read them, and a notes app would only be a second place for the same text.

You keep a handful of plain-text notes in a folder: a shopping list, a few addresses, a list of film recommendations. Notepad and File Explorer. At ten files, a folder is a perfectly good notes app.

I wrote a longer version of that last point for the Mac, where there is no Notepad at all; on Windows you are better off than you might think.

Where a folder of files runs out

It runs out in the same place for most people: somewhere past a few dozen files, when finding last March's thing means remembering what you named it. Windows search will look inside files, but it is looking across your whole disk, not across your notes. And the moment you want a to-do list next to the notes, or to paste a table in, or to link one note to another, you are either learning more Markdown syntax or opening another app.

That is the point where a notes app earns its place. Whether it should store your notes as Markdown files or in something structured is its own argument, and I have made it at length in Markdown or rich text. The short version: the format matters less than whether you can get your writing back out in a form other software reads. Test the export, not the file extension.

Opening text files in Cyanote

Cyanote is a desktop app that keeps notes, to-dos and clipboard history in one window, on your own machine, with no account and no sync. It started on the Mac, and there is now a Windows edition on the Microsoft Store. Here is what it does with .txt and .md files there, and nothing I have not checked in the code.

It registers for the usual text extensions. The Windows edition declares .txt, .md, .markdown, .text and .log to Windows, so Cyanote appears under Open with for those files. It does not make itself the default — Windows leaves that to you, through the Default apps page above. Opening .txt files this way is one of the things I have tested on a real Windows laptop, not just compiled.

The file becomes a note, linked to where it lives. An opened file arrives as a code note: Cyanote's plain-text editor, monospace, with syntax highlighting chosen from the contents. It is not converted into anything, so what you see is the file's text, character for character. Above it sits a File on disk bar with the file's full path — deliberately the full path, so you know which notes.md you are looking at — and buttons to show it in File Explorer, copy the path, or unlink it.

Markdown gets a preview. If the file ends in .md or .markdown, or its contents read as Markdown, the note has a Code / Preview switch. Code is the source; Preview renders headings, lists, tick boxes, tables, links and code blocks. The same idea as VS Code's preview, without VS Code.

Saving back is explicit. Your edits are stored in Cyanote as you type, but they do not reach the file until you press Ctrl+S or Save to file. Then the whole file is written in one go — the old version is replaced only once the new one is complete, so a crash mid-save cannot leave you with half a file. Save a copy writes the note somewhere else and follows the new file from then on.

It will not quietly lose edits. If you unlink a note, or move it to the trash, while it holds changes the file never received, Cyanote asks first and offers to save them.

Three limits, because they are real:

  • Opening the same file twice makes two notes. Each Open with is a new note linked to that path. If you already have one, open that instead.
  • It does not watch the file. If something else changes the file after you opened it, the note does not update, and Ctrl+S writes your version over theirs. For a file another program is actively writing to, use that program.
  • Files need to be UTF-8. Cyanote reads text as UTF-8. A file saved in another encoding, such as UTF-16, will not open in it.

If a lot of your text files are really snippets — config, scripts, commands you keep retyping — notes and code in one app is about exactly this kind of note, and two kinds of attention about keeping the prose and the code apart.

Writing Markdown in ordinary notes

A code note is the file as text. An ordinary note in Cyanote is the other kind: a document editor with headings, lists, tables, tick-box to-dos and links between notes. It stores its notes structured rather than as .md files, but you type it the way you would type Markdown.

At the start of a line, # and a space makes a heading (## and ### for smaller ones), - starts a bullet list, 1. a numbered one, [] a to-do, > a quote, three backticks a code block with highlighting, and --- a divider. Ctrl+N makes a new note and Ctrl+Shift+N a new code note. For anything longer than a page, writing a long document in a notes app covers what changes.

Bringing a folder in, and getting it back out

If you have a folder of Markdown notes from somewhere else, opening them one at a time is the wrong tool. In Settings > General > Backup there is Import Markdown files: pick any number of .md, .markdown or .txt files and each becomes an ordinary note. Headings, lists, tick boxes, quotes, links, tables and fenced code blocks come across as themselves. What the importer does not understand stays as the literal text you wrote rather than being dropped — images arrive as their alt text, YAML front matter as plain lines — and importing the same files twice does not duplicate them.

Getting a note out is a right-click in the sidebar: Export as Markdown… writes a .md file wherever you choose. Headings, lists, to-dos, tables and code blocks with their language all go out as standard Markdown, with literal asterisks and brackets escaped so they do not turn into formatting on the other side. Links between notes go out as [[Note title]], a label rather than a link to a file that is not there. Code notes export as their text, suggested as .txt. And a note you opened from a file is already a file: that is what Ctrl+S is for.

Whether any app's export is good enough is worth checking before you need it, and getting your notes out is the fifteen-minute version of that check.
